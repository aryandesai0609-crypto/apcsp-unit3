Drill: What runs first?

Focused practice on ordering: sequential code vs. code inside onEvent, and how setScreen / setProperty (last one wins) differ from console.log (every line shows). Instant feedback after each answer. Questions and answer choices are shuffled every time.

The rule
1. Every statement outside an onEvent runs first, top to bottom, before the user can do anything.
2. Statements inside an onEvent run only when that event happens, in the order the user triggers events. Inside one handler, top to bottom.
3. Where an onEvent sits in the file does not matter.
4. setScreen and setProperty replace: you only see the last one that ran. console.log adds a line every time.
5. A button's onEvent can only fire if the button is on the screen currently showing.
